# 조립형 프롬프트 ① 부산 지역 키워드 맵 (두 트랙 공통)

> 세 칸만 내 말로 채워 저장한 뒤, Claude Code에 '이 파일을 열어 할 일을 실행해 줘' 한 줄을 보냅니다(공통 실습서 2단계). 붙여 넣기가 편하면 '완성 프롬프트' 블록을 통째로 붙여도 됩니다.
> 칸을 비워 두면 Claude는 아무 기준 없이 '부산 유명한 것' 목록을 줍니다. 그게 `examples/`의 Before입니다.

## 칸 채우는 법

| 칸 | 이렇게 쓰면 약해요 | 이렇게 쓰면 좋아요 |
|---|---|---|
| [1. 나의 기획 목적] | 부산 키워드 조사 | 6주 뒤 영도를 배경으로 한 로컬 브랜드 페르소나를 만들 재료 찾기 |
| [2. 최우선 판단 기준(우선순위)] | 유명한 것 | ① 출처 URL이 있는 것 ② 내 트랙 산출물로 이어지는 것 ③ 최근 1년 안의 것 |
| [3. 타깃 대상 및 제외할 노이즈] | 없음 | 타깃은 20~30대 부산 밖 방문객. 2025년에 끝난 행사, 같은 축제의 중복 행, 출처 없는 블로그 글은 뺀다 |

## 완성 프롬프트 (세 칸을 채운 뒤 통째로 붙여 넣기)

```text
[1. 나의 기획 목적]
우리 팀이 남은 기간 동안 '부산에만 있는 무엇'으로 고른 이재모피자를 데이터로 분석하기 위해, 이재모피자에 사람이 몰리는 이유(웨이팅, 리뷰 반응, 관광객 방문)와 관련된 장소·키워드·이야기를 한 장에 모은다

[2. 최우선 판단 기준(우선순위)]
① 근거 등급: inputs 파일의 행 번호로 근거를 댈 수 있다.
② 시점: 2026년에 나왔거나 지금도 유효한 정보다.
③ 트랙 산출물 연결: 내 트랙 산출물로 이어진다 (예: 리뷰 분석 → 수요 예측, 웨이팅 → 원격 대기 앱 아이디어)

[3. 타깃 대상 및 제외할 노이즈]
주말이나 연휴에 부산을 찾는 타지역 20~30대 관광객 (이재모피자 웨이팅 줄의 주된 손님층)
뺄 것:
① 이재모피자와 관계없는 일반 부산 관광 행 (해수욕장, 축제 등 피자·맛집·웨이팅 언급이 없는 것)
   - 예외: 피자 언급이 없어도 본점이 있는 남포동·광복동(중구) 일대에서 아직 끝나지 않은 행사는 '웨이팅 비교 시점 후보'로 남긴다.
   - 예외: 부산 방문객 흐름을 직접 다루는 데이터랩 지표(datalab_*.csv)는 일반 관광 행으로 보지 않는다.
② 2025년 이전 행사·이벤트 행. 단, 이재모피자 매장이 있는 남포동(중구)·부산역(동구)·서면(부산진구) 근처에서 2025-11 이후 열렸거나 열릴 행사는 ①에 걸려도 웨이팅·리뷰 비교 기준일로 남긴다
③ 같은 내용이 출처만 다르게 반복된 중복 행 (먼저 나온 행 하나만 남김)
④ 광고·협찬 표시가 있는 블로그나 리뷰 행

할 일:
1. `inputs/`에 실제 있는 CSV만 읽어. 파일별 행 수와 컬럼 이름을 먼저 표로 보여 줘. 현재 예상 파일은 `busan_festivals.csv`와 `datalab_*.csv` 5개이며, 없는 파일을 찾거나 만들었다고 하지 마.
2. 위 [2]의 순서대로 프로젝트에 맞는 키워드 12개 이상을 골라 `keyword-map.md`의 표를 채워. 묶음은 3개 이상.
3. 키워드마다 근거를 '어느 inputs 파일의 데이터 행 번호' 또는 '직접 확인한 웹 페이지 URL'로 적어. 웹 원문을 열지 않았으면 상태에 '확인 필요'라고 써. 근거는 표의 '근거' 칸에 적어.
4. [3]의 제외 조건에 걸린 행은 넣지 말고, keyword-map.md의 '뺀 것' 표에 이유와 함께 따로 적어.
5. 회사나 기관이 밝히지 않은 이유는 '가설:'로 시작해.
6. 다 쓰면 `examples/before-after-data-note.md`의 After와 비교해서 모자란 점 3가지를 말해 줘.
```

## 붙여 넣은 뒤 확인

- [ ] 키워드마다 근거(파일 행 또는 URL)가 있다
- [ ] '뺀 것' 목록이 있고, 내가 [3]에 쓴 조건과 맞다
- [ ] 숫자는 inputs 파일의 숫자와 똑같다(Claude가 반올림하거나 바꾸지 않았다)
